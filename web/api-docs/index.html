Monitor OSD Community. API v1

Publiczna część API służy wyłącznie do odczytu i obsługuje CORS dla dowolnej domeny. Zwraca tylko dane dopuszczone przez politykę publikacji. Odczyt nie uruchamia pobierania danych od operatorów. Administracja, diagnostyka i porównanie lokalizacji wymagają uwierzytelnienia we własnej instalacji; demo blokuje zapis i usługi lokalizacyjne.

GET /api/v1/summary

Liczniki, stan świeżości i identyfikator migawki.

GET /api/v1/sources

Stan odczytu danych pięciu operatorów: PGE, TAURON, ENERGA, ENEA i Stoen.

GET /api/v1/locations

Wszystkie monitorowane lokalizacje w jednej odpowiedzi. Odpowiedź zawiera wyłącznie zatwierdzone do publikacji pola, kody lokalizacji, współrzędne orientacyjne lub zadeklarowane oraz liczniki komunikatów. Wyposażenie i prywatne dowody nie są publikowane.

fetch('https://osd-demo.bieda.it/api/v1/locations').then(r => r.json()).then(console.log)

GET /api/v1/localities

Unikalne miejscowości pogrupowane według identyfikatora SIMC wraz z listą obiektów.

GET /api/v1/map

Jedna spójna migawka używana przez główny panel i SNUT: lokalizacje, zdarzenia, źródła, aktualność danych i liczniki.

GET /api/v1/objects

Obiekty. Parametry: q, view, fields, limit, offset.

GET /api/v1/events

Zdarzenia. Filtry: object_id, source, type, time_phase, from, to.

fetch('/api/v1/events?source=pge&limit=10').then(r => r.json()).then(console.log)

GET /api/v1/display/{object_id}

Niewielka odpowiedź JSON dla ESP32 i prostych wyświetlaczy. Brak zdarzeń nie jest potwierdzeniem zasilania. Zawsze sprawdź data_status.

GET /api/v1/history

API udostępnia archiwum zmian zapisanych w SQLite. Domyślnie zwraca 50 wpisów na stronę. Maksymalny rozmiar strony to 200 wpisów. Filtry: source, object_id, from i to (daty ze strefą czasową). Początek przedziału jest włączony, a jego koniec wyłączony. Pobieraj kolejne strony wskazane w polu next, aż API zwróci wartość null. Po HTTP 409 zacznij od pierwszej strony.

history_id to stały UUID. before i after zawierają stan przed zmianą i po niej. snapshot oznacza stan zapisany w migawce. time_phase_at_recording dotyczy chwili zapisu. complete=false wskazuje, że archiwum nie obejmuje całej przeszłości. Zachowuje ono wpisy dotyczące usuniętych obiektów i wyłączonych źródeł. Publiczny odczyt stosuje aktualną politykę publikacji.

Eksporty JSON/CSV pokazują do 200 ostatnich wpisów o zakończeniu publikacji lub dopasowania komunikatu, z jawnym zakresem i ograniczeniem. Publiczną część archiwum można odczytać przez kolejne strony historii. Właściciel instalacji może wyeksportować własną kopię bazy narzędziem history-export. Publiczny odczyt nie uruchamia pobierania danych od operatorów.

Pamięć podręczna i CORS

Jeśli odpowiedź zawiera ETag, można wysłać go jako If-None-Match; brak zmian daje HTTP 304 bez treści. Demo usuwa ETag z odpowiedzi API i ustawia Cache-Control: no-store. Prywatne odpowiedzi nie udostępniają publicznego CORS.

Geoportal: zapisane porównanie lokalizacji

GET /api/v1/objects/{object_id}/location-review odczytuje zapisany wynik bez wysyłania zapytań do GUGiK. Wymaga sesji administratora; demo blokuje ten odczyt. Wartości current i expired określają aktualność wyniku. Status consistent oznacza zgodność danych rejestru. Nie potwierdza adresu obiektu ani stanu zasilania.

POST /api/location/check z JSON {"object_id":"ID"} uruchamia porównanie z uwzględnieniem limitu zapytań albo zwraca wynik z pamięci podręcznej. Wymaga sesji administratora, zgodnego nagłówka Origin i tokenu CSRF. W demo jest zablokowane. Nie zmienia obiektu. Błędy: 400 błędne dane, 404 nieznany obiekt, 409 zmiana podczas odczytu, 429 przerwa wymagana przez dostawcę, 503 problem lub wyłączenie funkcji.

Zasilanie rezerwowe obiektu

Podczas dodawania lub edycji obiektu możesz zapisać rodzaj agregatu, dodatkowy tor zasilania i uwagi, np. „Sprawdzić paliwo” lub „Agregat uruchamiamy na miejscu”. Agregat i dodatkowy tor zasilania mogą występować jednocześnie. SZR oznacza samoczynne załączanie rezerwy.

Po zalogowaniu informacje są widoczne na liście obiektów, w oknie opisu punktu na mapie i przy komunikatach. „Nie uzupełniono” nie oznacza braku agregatu. Użytkownik opisuje wyposażenie. Aplikacja nie mierzy poziomu paliwa, nie steruje wyposażeniem i nie potwierdza jego działania. Edycja wyposażenia nie wpływa na współrzędne, adres, wynik weryfikacji ani dopasowanie komunikatów.

Prywatny katalog administratora zawiera power_supply z polami generator, secondary_feed i notes. Kody: unknown (nie uzupełniono), none (brak), manual (obsługa ręczna), szr (układ SZR). Uwagi do 1000 znaków są dostępne tylko uprawnionemu administratorowi. Publiczna projekcja pomija całe pole wyposażenia. PATCH zmienia tylko podane podpola. Historia i treść powiadomień pozostają bez zmian.

{"power_supply":{"generator":"szr","secondary_feed":"manual","notes":"Sprawdzić paliwo"}}

Ten JSON można wysłać metodą PATCH do /api/admin/objects/ID_OBIEKTU. Pobierz ID z katalogu administratora. Wymagane są sesja, zgodny Origin i token CSRF; demo odrzuca tę operację. Zmiana pola generator nie usuwa dodatkowego toru zasilania ani uwag.

„Pokaż punkty i obszary operatorów” podaje liczbę narysowanych elementów albo informację o braku geometrii. Przewiń do mapy i przybliż wybraną okolicę, aby zobaczyć małe punkty.
